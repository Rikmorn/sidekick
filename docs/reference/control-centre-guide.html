The control centre, row by row

sidekick adds a few rows to the Claude Code session you work in: who needs you, what your workers are doing, how the board stands, and which profile is loaded. You move between sessions with Claude Code's own agent view.

Every screen here is a real session, captured on Claude Code 2.1.309 with sidekick at 66ed52e, then redrawn. Your colours follow your terminal theme. Session names from other work are replaced with neutral ones.

1The model

Run one main per terminal tab. It is the conversation you work in, and the only kind of session that draws the desk and the board. Everything else runs in the background, and agent view is how you reach it.

RoleWhat it isWhat sidekick draws there
MainThe session you work in, before and after ←The desk's band and pane, the board's line and pane, the footer's profile label
WorkerA session your main dispatched, in its own worktreeA grey signpost under the prompt that names its main and the keys back
OtherAny other background session, such as a bare claude --bgOnly the footer's profile label

← works on an empty prompt. The first time your main launches a worker, sidekick fixes the main's name with /rename once the session is idle. That keeps the name the worker points back to. Press ← before then and the name is lost for that worker.

2Your main at a glance

With two workers out, one of them stopped on a permission prompt, the bottom of your main looks like this.

The board's line

In a repository tracked on a GitHub board, one line under the prompt says how the milestone stands.

● on track
The last status update says so, and nothing has drifted.
✓ complete
The milestone is done.
▲ at risk
The last status update flags a risk.
▲ drift · …
The board and the repository disagree, such as unpushed commits or a stale card. The detail names it.
✗ off track
You marked the milestone off track.
○ inactive
The last status update marks the milestone inactive.

The line refreshes when a session starts, when /board opens, and after a commit, a push, or a board write. It has no clock. When a refresh fails, the time reads refresh failed HH:MM and the rest is the last good reading.

3Panes and commands

Each command shows or hides its pane. Below 110 columns, or on the classic screen, a pane sits inline above the prompt. In fullscreen from 110 columns it docks on the right.

CommandShowsKeysCloses with
/deskEach worker's state, tokens, plan, and last commit, then every other sessionStay with the prompt/desk again
/boardThe board's six-line brief and its linkStay with the prompt/board again
/profileThe profile, what it hides, and what loaded into contextTaken by the pane: ↓ scrolls at onceEsc, or /profile again

A pane that holds the keyboard draws its frame bright. To scroll /desk or /board, press Ctrl+X Tab to give them the keys, then ↓. Esc hands the keys back and leaves the pane open. A pane with more rows than room says so in its first row.

4Getting around

← on an empty prompt opens agent view, with the session you left selected.

KeyWhereWhat it does
←Any session, empty promptOpens agent view. In a session you are attached to, it detaches and starts nothing.
EnterAgent viewOpens the selected session. On a group header it folds or unfolds the group.
EscAgent view, right after ←Returns to your conversation, now running in the background process, like Enter.
↑ ↓Agent viewMoves between rows. Rows reorder as their states change.
Alt+1…Alt+9Agent viewOpens session N in this folder. Pin your main with Ctrl+T so Alt+1 is always your main.
Ctrl+XAgent viewStops the selected session. A second press soon after deletes it, worktree included. Check the selection first.
Ctrl+C twiceAnywhereQuits the tab. Background sessions, your main among them, keep running.
claude attach <name>A shellOpens a running session by name or part of it. A stopped one opens by id only.
/stopAn attached sessionStops it, keeping its transcript and worktree. /exit only detaches.

Claude Code's agent view documentation has the full list. An idle background session stops after about an hour unless pinned, and resumes when you open it.

Ctrl+Z does two different things

In a session you started in the terminal, Ctrl+Z suspends Claude Code to the shell. Type fg to bring it back, views and all.

In a session opened with claude attach, Ctrl+Z closes the attach and the session runs on in the background. Nothing is left stopped.

The /desktop trap

Claude Code has its own /desktop command, which hands the session to the Claude desktop app. Where sidekick's /desk is registered, it lists first. Where it is not, /desktop lists first, and Enter runs it.

5Working with workers

A worker runs one plan in its own worktree while you keep working in your main. You choose the worker mode when a plan is ready; the main does the rest.

StepWhat happensWhat you see
DispatchThe main writes a brief and runs sidekick worker dispatchThe launch output, and once the main is idle, a /rename that fixes its name
WatchWithin 10 seconds the worker joins the deskThe band's workers line. In fullscreen from 144 columns, the desk pane opens by itself
QuestionsThe worker messages its questions to the main and waitsThe message in the main's transcript. A permission prompt shows under needs you
Look in←, select the worker, EnterThe worker's signpost under its prompt
SteerThe main writes a ruling to the rulings file and messages the workerThe worker's transcript, once you look in
FinishThe main reviews the branch, integrates it, and runs sidekick worker finishThe report saved; the worker leaves the desk

6When things look wrong

You seeIt meansDo this
⚠ desk: …The desk's last refresh failed, or listed a warningRead the reason. A slow listing clears on the next tick
⚠ board: …The board could not be read when you asked/board closes the pane and clears the row; open it again to retry
refresh failed HH:MMThe board line shows its last good readingIt refreshes at the next commit, push, or /board
No band or footer label after ←The backgrounded main came up without sidekick's mods, seen once (#250)Avoid Enter on /desk there. Note the time and tell your main to add it to #250
blocked · blockedA waiting session that gave no reason, printed twice (#253)Nothing; this plan fixes the print
⚠ sidekick: no profile settingsThe session was not launched with a profileNothing, or launch with sidekick profile launch <name>
sidekick: its mods are not runningThe mods did not start in this sessionRun bun run check:mods in the sidekick repository
A worker's signpost names an old mainThe main was renamed after the worker startedUse the new name in agent view

A hot reload of sidekick's code turns a backgrounded main into an ordinary background session until you stop and reopen it. While a permission prompt is open, the band, the panes, and the signpost stay hidden.

7Settle by use

These are open on purpose. Try each while you work, then tell any main what you found: “file this: …”. Each finding becomes its own issue.

The control centre's shape

The commands
Do all three of /desk, /board, and /profile earn their place? Would the desk serve you better always open?
The keys
/profile takes the keys when it opens; the other two leave them with the prompt. Which feels right?
The desk's order
The pane lists workers before other sessions, so a long list can hide a waiting session at the bottom. Does that bite?
Which main
The prompt's border shows a session's name once it is set. Is that enough to tell your mains apart, or should a main say so?
The notice
Every session without a profile shows ⚠ sidekick: no profile settings. Useful, or noise?
